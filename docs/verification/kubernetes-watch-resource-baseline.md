# Kubernetes watch resource baseline evidence

This matrix records observable cleanup for F4 acceptance cases. The evidence is split by boundary: synthetic Rust tests observe producer tasks, projection and queue counters, watch permits, and live synthetic API connections; renderer tests observe shared owner release through the transport contract; native tests use real Tauri channels; the C4 harness records namespace and host restoration. It does not infer cleanup from a cleanup method returning alone.

The synthetic API server increments an active-connection counter for each accepted connection and decrements it when its connection task exits. `SyntheticApiserver::stop` joins all connection tasks and asserts the observed count is zero. Queue and projection counters are sampled directly by the cancellation, overflow, relist, and shutdown tests. Store-level tests sample the watch semaphore and session registry after stop, close, and shutdown.

**Limit:** native OS process shutdown while a Tauri watch is active is covered at the session-store shutdown boundary and by the real Tauri channel/session-close tests; the WebDriver run does not forcibly terminate the application during an outstanding watch. A direct `Channel.send` transport error is not induced; consumer disappearance is observed as a missing acknowledgement and bounded termination.
